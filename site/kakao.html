01 · 프로젝트 소개

왜 체결 메시지를 자동으로 수집하려 했나

주식 체결이 이뤄지면 증권사(한국투자증권) 카카오톡 채널로 체결 안내 메시지가 도착합니다. 체결가, 수량, 주문번호가 담긴 긴 메시지인데, 이걸 매매일지에 옮겨 적는 일은 번거롭고 빠뜨리기도 쉽습니다. 휴대폰이 스스로 체결 메시지를 읽어 서버로 보내 주면, 기록은 자동으로 쌓이고 사람은 매매에만 집중할 수 있습니다.

문제는 카카오톡 알림만으로는 긴 메시지를 온전히 가져올 수 없다는 점입니다. 이 프로젝트는 그 한계를 확인하고, 알림이 아니라 채팅 화면 자체를 읽는 방식으로 우회해 전문(全文)을 서버까지 전달하는 핵심 기술을 먼저 검증한 기록입니다. 자동 실행의 마지막 단계와 DB 저장은 아직 남아 있으며, 이 페이지에서는 검증된 것과 아닌 것을 엄격히 구분해 표시합니다.

04 · MacroDroid 설정

트리거와 동작 순서

수동 실행은 검증이 끝났고, 알림 트리거 자동 실행은 최종 검증이 남아 있습니다. 설정값은 복사해서 쓸 수 있습니다.

플로팅 버튼 kakao_read 검증 완료

수동 테스트용 트리거. 버튼을 누르면 카카오톡 실행부터 서버 전송까지 전체 처리가 한 번에 실행됩니다. 현재까지의 모든 검증은 이 경로로 수행했습니다.

카카오톡 알림 수신 최종 검증 필요

자동 실행용 트리거. 알림이 오면 같은 동작이 무인으로 실행되도록 연결할 예정이며, 실제 체결 알림 상황에서의 동작은 아직 검증하지 않았습니다.

06 · 기술적 한계

알고 넘어가야 할 것들

잠금·화면 꺼짐 상태

화면이 꺼져 있거나 휴대폰이 잠긴 상태에서는 UI 자동조작이 실패할 수 있습니다. 무인 자동 실행의 가장 큰 변수입니다.

화면에 보이는 것만 읽힌다

화면 텍스트 읽기는 현재 화면에 표시된 내용만 가져옵니다. 스크롤 밖에 있거나 화면에 표시되지 않은 메시지는 추출할 수 없습니다.

카카오톡 UI 변경에 취약

카카오톡 화면 구조나 View ID가 업데이트로 달라지면 채팅방 자동 열기와 텍스트 읽기가 깨질 수 있어, 그때마다 설정을 손봐야 합니다.

개인정보 전송 위험

화면 전체를 읽는 방식이라 비밀번호 등 민감정보가 화면에 있으면 함께 전송될 수 있습니다. 전송 전 민감정보 차단은 아직 구현하지 않았습니다.

과거 메시지를 현재 거래로 오인할 위험

채팅방에 남은 과거 체결 메시지를 오늘 거래로 저장하면 안 됩니다. 거래일 검증은 아직 구현하지 않았으므로, 지금 단계의 수집 데이터는 기록용으로만 봅니다.

중복 방지 미구현 · 테스트와 실전의 구분

같은 메시지가 중복 전송·저장되는 것을 막는 장치도 아직 없습니다. 또한 현재 서버는 테스트 API 수신까지만 확인한 상태로, 실제 매매일지 DB 저장 기능과는 구분됩니다.

07 · 향후 개발

남은 과제

자동 트리거 검증이 먼저, 그다음이 서버 쪽 분석과 DB 연결입니다.

    결론 — 핵심 기술은 검증됐다

    카카오톡 알림의 길이 제한은 채팅 화면의 텍스트를 직접 읽는 방식으로 우회할 수 있고, 그렇게 추출한 긴 체결 메시지를 개인 서버까지 온전히 전달할 수 있음을 확인했습니다. 채팅방 자동 열기부터 전문 전송까지, 수동 실행 기준으로는 전체 흐름이 동작합니다.

    남은 일은 분명합니다. 실제 체결 알림으로 무인 자동 실행을 검증하고, 서버에서 체결 여부·거래일·중복을 걸러낸 뒤에야 매매일지 DB에 연결합니다. 완료되지 않은 단계를 완료로 표시하지 않는 것이 이 기록의 원칙입니다.
