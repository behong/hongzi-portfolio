Cloudflare 하나로 집 서버 사이트 굴리기 — 터널·Pages·Workers·R2 활용과 정리 기록

2026. 11. 06·인프라 정리 기록 · Cloudflare 전수 조사

전수 조사 — 생각보다 층이 많았다

이 블로그를 포함해 집 PC 한 대에서 여러 사이트를 운영하고 있다. 포트폴리오, 아내의 부동산 사이트, 여행 제휴 사이트, 개인 매매일지까지. 전부 Cloudflare를 경유해 공개되는데, 사이트가 하나씩 늘 때마다 붙인 구조라 전체 그림을 그려 본 적은 없었다. 오늘 계정을 전수 조사해서 지도를 만들었다.

구조는 다층이었다. 지금 운영 중인 사이트들은 프로젝트마다 전용 터널을 하나씩 갖고 있다(포트폴리오·부동산·매매일지·여행, 모두 4개). 그런데 그 아래에 초기에 만든 통합 터널 하나가 여전히 살아서, 쇼핑 단축 링크·웹훅·집 NAS·동기화·시장 데이터용 서브도메인 5개를 담당하고 있었다. 새 방식과 옛 방식이 겹쳐 굴러가는, 오래된 집의 배선 같은 모습이었다.

역할 분담 — PC가 꺼져도 죽지 않는 층

조사하면서 확인한 설계의 핵심은 '어느 층이 Cloudflare 쪽에 있는가'였다. 집 서버가 아니라 Cloudflare에 올라간 것들은 정전이나 PC 재부팅과 무관하게 유지된다.

  • 정적 사이트는 Pages — 핫딜 사이트처럼 완성된 페이지를 올려 두는 곳은 PC 전원과 무관하게 열린다
  • 짧은 링크와 상태 체크 같은 가벼운 로직은 Workers — 서버 없이 엣지에서 바로 실행된다
  • 가격 스냅샷 같은 데이터 파일은 R2 — 사이트가 읽는 데이터가 PC가 아니라 오브젝트 스토리지에 있어 링크가 죽지 않는다
  • 터널은 마지막 층 — 예약 접수나 일지처럼 실제로 집 서버가 일해야 하는 서비스만 터널로 연결한다. PC가 꺼지면 멈추는 것은 이 층뿐이다

오늘 한 정리

  • 통합 터널에 남아 있던 그림자·죽은 라우트 5개 삭제 — 옛 서비스의 흔적이 남아 있으면 잘못 연결되거나 보안 구멍이 될 수 있다
  • 스테이징용 Worker와 옛 Pages 프로젝트 삭제 — 테스트용으로 만들었다가 잊힌 것들이다
  • 운영을 끝낸 사이트 1개 종료
  • 삭제 뒤 본진 사이트 3개가 정상 응답하는 것까지 검증하고 나서야 정리를 끝냈다 — 지우는 작업일수록 확인이 본체다

교훈 셋

  • 도커만 믿으면 안 된다 — 컨테이너만 챙겨서 서버를 이전하면, 호스트에 직접 설치된 데이터베이스나 터널 같은 서비스가 누락된다. 이전할 때 가장 먼저 빠지는 층이 호스트 작업이다
  • 그래서 '서버 이전 체크리스트' 문서를 만들었다 — 호스트에서 한 작업 전수를 목록으로 남겨서, 다음 이전은 이 목록을 따라가며 빠짐없이 옮길 수 있게 했다
  • 두 단계 서브도메인의 함정 — data.hot 같은 2단계 서브도메인은 무료 와일드카드 인증서가 덮는 범위 밖이다. 이 경우는 데이터가 있는 R2 쪽 인증서로 실제로 동작 중이라 조치 불요로 판정했지만, 모르고 만들면 접속 오류로 나타나는 종류의 함정이다

마치며

사이트가 늘 때마다 급한 대로 붙인 구조는, 어느 순간 아무도 전체 그림을 모르는 상태가 된다. 오늘처럼 전수 조사해서 지도를 그리고, 죽은 길을 지우고, 다음 이전을 위한 체크리스트까지 남겨 두는 정리가 집 서버 운영의 본체인지도 모르겠다. 기능 추가보다 지도가 먼저다.

출처 · 바로가기

  • Cloudflare Tunnel 공식 문서 공인 IP를 열지 않고 집 서버를 안전하게 공개하는 터널의 개념과 설정 문서입니다.
  • Cloudflare Pages 공식 문서 정적 사이트를 엣지에 배포하는 Pages의 문서입니다. PC가 꺼져도 유지되는 층의 한 축입니다.
  • Cloudflare Workers 공식 문서 짧은 링크나 상태 체크 같은 가벼운 로직을 서버 없이 실행하는 Workers 문서입니다.
  • Cloudflare R2 공식 문서 가격 스냅샷 같은 데이터 파일을 두는 오브젝트 스토리지 R2의 문서입니다.
