Codex에 도커까지 맡기는 법 — /permissions에서 Full Access 켜기

2026. 11. 19·개발 도구 팁 · Codex CLI 권한 설정

왜 도커에서 자꾸 멈추나

Codex CLI의 기본 권한은 'Ask for approval'이다. 작업 폴더 안의 파일을 고치고 명령을 돌리는 건 되지만, 폴더 밖으로 나가거나 인터넷이 필요한 명령은 매번 승인을 묻거나 아예 막힌다.

문제는 도커가 그 경계 밖에 있다는 거다. 도커 데몬도, 빌드·컨테이너 재시작 같은 배포 작업도 전부 작업 폴더 밖에서 일어난다. 집 서버 사이트들을 Codex로 만들고 배포하는 우리 환경에서는, 배포 한 번에 승인 창이 몇 번씩 뜨거나 도커 접근 자체가 거부돼 작업이 끊기는 일이 실제로 있었다.

켜는 법 — 세 번이면 끝난다

  • Codex 실행 중 입력창에 /permissions 를 입력한다
  • 권한 목록에서 3. Full Access를 선택한다 — 설명 문구는 'Codex can edit files outside this workspace and access the internet without approval'
  • 경고 확인창에서 '1. Yes, continue anyway'를 고르면 이 세션에 바로 적용된다

Full Access의 정체 — 스위치 두 개

Codex의 권한은 사실 두 개의 독립 설정이다. 하나는 샌드박스 — 명령이 파일과 네트워크 어디까지 닿을 수 있는가. 다른 하나는 승인 정책 — 언제 멈춰서 사람에게 묻는가.

Full Access는 이 둘을 한 번에 끝까지 여는 프리셋이다. 샌드박스는 danger-full-access(제한 없음)로, 승인 정책은 never(묻지 않음)로 바뀐다. 나머지 선택지는 이렇다. Ask for approval은 기본값으로 폴더 안에서만 일하고 필요할 때 묻고, Approve for me는 위험해 보이는 동작만 자동 검토에 맡기며, Read Only는 말 그대로 읽기 전용이다.

매번 켜기 귀찮으면 — 영구 설정과 실행 플래그

/permissions로 켠 건 그 세션에만 적용된다. 매번 켜는 게 귀찮으면 설정 파일에 박아둘 수 있다. ~/.codex/config.toml 맨 위에 approval_policy = "never" 와 sandbox_mode = "danger-full-access" 두 줄을 넣으면 이후 모든 새 세션에 적용된다.

한 번만 전권을 주고 싶으면 실행 플래그도 있다. codex --dangerously-bypass-approvals-and-sandbox (줄여서 --yolo). 플래그 이름에 'dangerously'가 대놓고 붙어 있는 건 우연이 아니다.

켰으면 지켜야 할 것

확인창의 경고 문구가 과장이 아니다. Full Access 상태의 Codex는 승인 없이 이 컴퓨터의 모든 파일을 고치고, 네트워크로 명령을 실행할 수 있다. 데이터 손실이나 유출, 예상 못 한 동작의 위험이 실제로 커진다.

그래서 우리 집 규칙은 세 가지다. 첫째, git이나 백업으로 되돌릴 수 있는 프로젝트에서만 켠다. 둘째, 작업이 끝나면 실제 결과 — 사이트 응답, 컨테이너 상태 — 를 직접 확인한다. Codex의 '완료했습니다'를 그대로 믿지 않는 건, 지시를 어기고 멋대로 처리한 전례가 있기 때문이다. 셋째, 돈이 움직이는 실주문 경로나 되돌릴 수 없는 삭제가 걸린 작업에서는 켜지 않는다.

마치며

승인 창을 사람이 일일이 눌러주는 게 일이 되면 자동화의 의미가 없다. 막힌 이유가 샌드박스 경계였다는 걸 알고 나면 답은 간단하다. 필요한 작업에만, 되돌릴 수 있는 환경에서만 전권을 주고, 확인은 사람이 한다.
